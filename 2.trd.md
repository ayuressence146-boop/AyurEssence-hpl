1. Technical Overview

AyurEssence is a practitioner-centered digital platform for conducting Ayurvedic Prakriti assessments, managing patient assessment history, generating explainable results, supporting practitioner-approved recommendations, securely sharing reports, scheduling follow-ups, and providing a supervised learning environment for students.

The system consists of three primary roles:

Doctor
Student
Patient

The backend is implemented as a modular monolith using FastAPI with Supabase PostgreSQL as the primary database and Supabase Auth + JWT for authentication.

12. Human-in-the-Loop Recommendation System

This is one of the major new features.

The recommendation system does not directly send AI-generated advice to the patient.

Architecture
Assessment Result
       ↓
System generates draft
       ↓
Recommendation Draft
       ↓
Doctor reviews
       ↓
Doctor edits if necessary
       ↓
Doctor approves
       ↓
Patient receives
APIs
POST  /api/recommendations/assessment/{assessment_id}/draft
PATCH /api/recommendations/{recommendation_id}/approve
Recommendation states
DRAFT
  ↓
UNDER_REVIEW
  ↓
APPROVED

Optional:

DRAFT
  ↓
REJECTED
Core technical rule

Only an approved recommendation can become patient-facing.

Draft ≠ Patient Advice

Approved Draft = Patient-Facing Recommendation

This preserves the practitioner-controlled model.

Standard response:

{
  "success": false,
  "error": {
    "code": "RESOURCE_NOT_FOUND",
    "message": "Resource does not exist"
  }
}

Status codes:

400 → Invalid input
401 → Unauthenticated
403 → Unauthorized
404 → Resource not found
409 → Invalid state/conflict
500 → Internal server error

Never expose:

Stack traces
Database credentials
SQL errors
Service-role keys
Internal implementation details

29. Technical Constraints

The system must not:

replace doctors
autonomously prescribe medicines
diagnose diseases
use an LLM as the final Prakriti calculation authority
expose raw database URLs for report sharing
allow students to finalize assessments
allow patients to access other patients' information
allow finalized assessments to be silently modified

The recommendation module remains human-in-the-loop.
